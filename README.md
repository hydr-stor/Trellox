# رِواق — أساس منصة متاجر عراقية

مشروع جديد مستقل بالكامل. الاسم مؤقت ويتغيّر من `shared/brand.ts`. لم يُربط بأي مشروع قديم أو Worker أو D1 أو R2 إنتاجي، ولم يُنشر. هذه المرحلة أساس عملي قابل للتشغيل، وليست منتجًا تجاريًا مكتملًا أو جاهزًا للإطلاق.

## التشغيل المحلي

المتطلبات: Node.js 24، npm 11، متصفح حديث. لا تحتاج حساب Cloudflare أو مفتاح API للتطوير المحلي.

```bash
npm ci --ignore-scripts
npm run db:migrate
npm run dev
```

افتح `http://localhost:5173`. الواجهة على 5173 والخادم المحلي على 8787. اترك عملية التطوير مفتوحة. `Wrangler` يستخدم D1 وR2 المحليين داخل `.wrangler/` فقط. أول مرة يطلب تطبيق migration محليًا؛ وافق. لا تستخدم `--remote`.

أنشئ حسابًا من `/register` لبدء متجر فارغ؛ لا تُزرع بيانات داخل وظائف الإنتاج.

### بيانات مثال اختيارية

في نافذة طرفية ثانية، والخادم شغّال:

```bash
npm run db:seed
```

- التاجر التجريبي: `demo@riwaq.test`
- كلمة مرور مثال محلي عامة: `Local-demo-2026!` — لا تستخدمها لحساب حقيقي.
- المتجر: `http://localhost:5173/s/dar-demo`
- بيانات الزبائن والعناوين والطلبات كلها أمثلة محلية، وليست مبيعات حقيقية.
- الصورة مولّدة بالذكاء الاصطناعي لتجربة العرض؛ ملف WebP محلي حوالي 160KB، وليست صورة منتج حقيقي.
- أرقام لوحة التحكم تُقرأ من D1، حتى عند استخدام seed؛ لا توجد إحصائيات مزيفة في الواجهة.
- seed يتحقق أن الخادم `APP_ENV=local`، ويتوقف إذا كانت منتجات المتجر التجريبي موجودة؛ ليس أداة استيراد إنتاج.

## ما يعمل الآن

- موقع تسويقي عربي RTL وصفحة باقات، فاتح وداكن، حركات محدودة تحترم `prefers-reduced-motion`.
- إنشاء حساب ومتجر ورابط فريد واشتراك تجريبي أساسي 14 يومًا داخل دفعة D1 واحدة.
- تسجيل دخول وخروج وجلسات HttpOnly، مع خزن hash للتوكن وانتهاء بعد 7 أيام.
- كلمات المرور scrypt N=16384,r=8,p=2، مع salt عشوائي لكل حساب. لا تُخزن كنص صريح.
- لوحة تاجر بأرقام حقيقية، قائمة طلبات حديثة، حالات فراغ وخطأ، ومؤشر طلبات جديدة يُحدّث كل 20 ثانية عند وجود جلسة.
- منتجات وصور محلية R2، تصنيفات، سعر صحيح بالدينار، سعر سابق اختياري، وإخفاء المنتج بدل الحذف.
- إنشاء عدة أنواع مقاس/لون بمخزون مستقل؛ تعديل تفاصيل المنتج ومخزون الأنواع الموجودة مع optimistic stock check.
- إعداد اسم وشعار ووصف وسياسة إرجاع، وأجور المحافظات. المنطقة والعنوان من إدخال الزبون؛ لا توجد أسعار منفصلة لكل منطقة بعد.
- متجر عام، بحث وتصنيف وترتيب، صفحة منتج، سلة محلية مفصولة لكل متجر، وطلب ضيف مع هاتف وعنوان عراقي ودفع عند الاستلام.
- السعر وأجور التوصيل تؤخذ من قاعدة البيانات؛ لا تُقبل أسعار السلة من العميل.
- idempotency مرتبط بالمتجر وبصمة تفاصيل الطلب؛ تكرار نفس الطلب بنفس المفتاح يعيد التأكيد السابق، وتغيير تفاصيله مع نفس المفتاح يرفضه. الواجهة تمنع الإرسال المتكرر وتحفظ مفتاح المحاولة مع hash فقط، بدون اسم أو هاتف أو عنوان في localStorage.
- SQL triggers تحجز المخزون داخل transaction لإنشاء الطلب وتمنع البيع الزائد حتى عند التزامن. الإلغاء يرجّع الكميات مرة واحدة.
- انتقالات حالات الطلب وتاريخ الحالة، ورابط تأكيد عشوائي 256-bit لا يعرض بيانات الزبون الشخصية، ويتحدث كل 20 ثانية.
- الاشتراك يُفحص على الخادم: 30 منتجًا في التجربة، 100 للأساسي المفعّل، 500 للثاني. المنتهي للقراءة فقط؛ طلب تفعيل مسموح.
- طلبات تفعيل اشتراك حقيقية بحالة pending؛ لا تمنح صلاحية مدفوعة ولا تخصم مبلغًا. الباقة الثالثة غير قابلة للتفعيل.

## الاشتراكات والتكاملات

لا توجد بوابة دفع، Instagram OAuth أو AI، ولا شركة توصيل مربوطة. الأسعار التجارية النهائية غير مقررة، لذلك الواجهة تقول «السعر عند التفعيل».

صلاحية Instagram في الباقة الثانية لا تعني اتصال الخدمة: حتى مع تفعيل الباقة يدويًا يرجع مسار التكامل 503 واضحًا. الباقة الأساسية تُرفض بـ403. تكامل التوصيل يرجع غير متاح دائمًا. لا تستخدم إعداد 21st MCP بوصفه مساعد Instagram؛ أدوات تصميم الواجهات مستقلة عن منتج المنصة.

لا يوجد مسار HTTP يفعّل اشتراكًا مدفوعًا. لاختبار الباقات **محليًا فقط**:

```bash
npm run subscription:grant -- dar-demo plus 30
```

هذه أداة تشغيل محلية متعمدة، تستعمل `--local` دائمًا وتكتب أثرًا في audit_events. آلية تحصيل المال وموافقة المشرف تحتاج بناء في المرحلة الثانية.

## الاختبارات والبناء

```bash
npm test
npm run build
```

الاختبارات تستخدم Miniflare مع Worker وD1 وR2 فعليين محليًا، وتغطي المصادقة وعزل مستأجرين، الحالات والصلاحيات، المخزون المتزامن، idempotency، الرفع، حدود المنتجات وانتهاء الاشتراك. `npm run build` يفحص TypeScript، يبني Vite، ويجهّز Worker بـ`--dry-run` فقط. لا ينشر ولا ينشئ أي موارد.

اختبار المتصفح يحتاج Chromium. في هذه البيئة `/usr/bin/chromium` متاح. شغّل dev وseed أولًا ثم:

```bash
npm run test:browser
npm run test:boundaries
# أو حدّد مسار متصفحك
CHROMIUM_PATH=/path/to/chromium npm run test:browser
```

اختبار المتصفح ينشئ حساب اختبار محليًا، ينشر منتجًا، يكمل طلب ضيف، يغيّر حالته من لوحة التاجر ويسجل طلب اشتراك. المعاينات في `docs/previews/` وتقرير المرور في `docs/browser-verification.json`. صور المعاينة قد تحتوي بيانات محلية تجريبية فقط. ليست اختبارات على Safari فعلي أو هاتف آيفون فعلي.

## العزل والأمان

كل متجر تاجر يُشتق من جلسة مالكه. استعلامات الموارد تقيد بـstore_id، والواجهات العامة تُرجع حقولًا محددة. فحص Origin يمنع الطلبات المتغيرة من مصدر آخر، والسماح المحلي محدود بـlocalhost/127.0.0.1 للمنافذ 5173 و8787. لا يوجد CORS مفتوح. JSON schemas تتحقق من القيم، upload أقصاه 3MB ويتحقق من magic bytes لـPNG/JPEG/WebP. مفاتيح جلسات الحساب مخزنة كـSHA-256. التسجيل/الدخول محدودان عبر D1 بـ10 محاولات لكل 15 دقيقة لكل IP ومسار.

الدفع والشحن والـAI منفصلة عن صلاحيات الاشتراك. أي تكامل لاحق يحتاج بوابة جاهزية مستقلة بالإضافة إلى الصلاحية. `workers_dev=false` وقيم D1/R2 محلية بأسماء جديدة؛ database_id صفري غير صالح للإنتاج. لا يوجد deploy script، ومساعد أوامر Worker يرفض النشر الحقيقي والأوامر غير المحلية. لا تعتبر ذلك بديلًا عن مراجعة إعداد إنتاج منفصل مستقبلًا.

الـcookies تصبح Secure وباسم `__Host-` عندما APP_ENV لا يكون local. إعداد الإنتاج غير موجود؛ يلزم تغيير البيئة والتخزين والهوست والنطاقات عن قصد. لا ترفع `.wrangler/` أو `.env` أو `.dev.vars` أو قواعد SQLite أو الأسرار. ملفات الأدوات `.codex/` محلية ومهملة في Git.

## حدود مهمة وما يلي

هذه دورة أساسية عملية للمنتج/الطلب/طلب الاشتراك، وليست SaaS تجاريًا مكتملًا. تفاصيل المرحلة الثانية في `docs/phase-two.md`. لا يوجد رفع عدة صور للمنتج أو إضافة أنواع جديدة بعد الإنشاء في الواجهة بعد؛ تحرير المخزون الحالي متاح. لا توجد إدارة منطقة بأجرة مستقلة أو pagination متقدم. إشعارات داخل التطبيق بقراءة دورية وليست push. محاولات checkout تحمي من التكرار بالمفتاح نفسه، وليست نظام كشف احتيال أو منع زبون من إنشاء طلبين متعمدين بمفتاحين جديدين.

لم يتم نشر الموقع على الإنتاج أو ربط موارد إنتاج. رفع الكود إلى GitHub منفصل عن نشر التطبيق.
