# المرحلة الثانية — بوابات قبل الإطلاق التجاري

## الهوية والتسويق
اختيار الاسم والحقوق والنطاق، صور فعلية للمتاجر، تسعير واشتراطات تجارية، صفحات قانونية محلية، SEO وفهرسة مستقلة لصفحات المنتجات (النسخة الحالية SPA)، وإتاحة صفحات المشاركة ببيانات OG خاصة لكل متجر/منتج.

## التجارة
إضافة/أرشفة الأنواع بعد إنشاء المنتج، مكتبة صور متعددة، تحسين الصور ومقاسات responsive، أسعار وتغطية المناطق داخل المحافظات، pagination للكتالوج والطلبات، سجل مخزون مستقل (حركات وتوريد وتسويات)، حجز/سياسات طلبات طويلة الأمد ومكافحة إساءة الاستخدام، إرجاع بعد التسليم واسترداد/مرتجعات، إشعارات push أو بريد عبر مزود حقيقي.

## الاشتراك والتكاملات
تسعير نهائي، لوحة مشرف وصلاحيات منفصلة، موافقة/رفض وتسوية الطلبات وإثباتات التحصيل، سجلات مالية وتواريخ وإلغاء/تجديد. لا تفعل paid access ذاتيًا من الواجهة. اختيار بوابة دفع عند وجود عقد ومفاتيح sandbox، والتحقق من webhooks وإعادة المحاولة والتسوية. مساعد Instagram يحتاج OAuth Meta، صلاحيات ومراجعة التطبيق، معرفة مقيدة بالمتجر، rate/cost limits وموافقة استخدام البيانات. التوصيل يحتاج شركة فعلية وAPI sandbox، اقتباس أسعار وحالات شحن وwebhooks قبل تفعيل الباقة الثالثة.

## بوابات الأمان والتشغيل
تحقق البريد وإعادة ضبط كلمة المرور وتدوير الجلسات، مسح/تصدير بيانات المستخدم وسياسة احتفاظ قابلة للتنفيذ، إزالة بيانات seed، تفعيل سياسة Secure cookies فعليًا على HTTPS، تحديد tenant/custom domain موثوق، caching/CDN وآليات invalidation، WAF/turnstile ضد الطلبات الآلية، limits لرفع الصور وحذف الأصول اليتيمة، فحص محتوى صور متقدم، تقييم كلفة KDF على Worker مدفوع وحدود CPU، اختبارات ضغط D1 واقعية ونسخ احتياطي/استرجاع مجرب، مراقبة أخطاء خالية من PII، أدوات مسح الجلسات ومحاولات الدخول وفق TTL، CI للمتصفح وa11y، Safari/iPhone فعلي على شبكة بطيئة.

## النشر
إنشاء موارد Cloudflare جديدة مخصصة فقط للمشروع، مراجعة migration والـbindings، staging مع بيانات اختبار، مراجعة بشرية وموافقة نشر صريحة. لا تستخدم معرفات أو أسرار مشروع آخر. لا توجد أي موارد إنتاج مرتبطة الآن.
